## Solution
I explored the main concepts one by one:

- **File permissions:** understanding read, write and execute permissions
- **Ownership:** changing user and group ownership of files and directories
- **Umask:** controlling default permissions when creating new files and directories
- **SetUID:** a program can execute with the file owner's privileges
- **SetGID:** directories can preserve group ownership across shared folders
- **Process permissions:** effective user IDs, and how Linux determines what a process can access
- **Sticky bit:** controls file deletion in shared directories

## Octal permissions, broken down
Each permission has a number: **read = 4, write = 2, execute = 1**. Add them up for each set of people:

| Digits | Meaning |
|---|---|
| 7 = 4+2+1 | read, write, execute (`rwx`) |
| 6 = 4+2 | read, write (`rw-`) |
| 5 = 4+1 | read, execute (`r-x`) |
| 4 | read only (`r--`) |
| 0 | no access (`---`) |

A four-digit value has this order: **special digit, owner, group, others**. The special digit is **4 = SetUID, 2 = SetGID, 1 = Sticky bit**.

- **`4755`:** special `4` (SetUID), owner `7` (rwx), group `5` (r-x), others `5` (r-x). Shows as `-rwsr-xr-x`. The `s` in the owner's execute spot means SetUID is on. The `passwd` command is a typical example: it runs with its owner's (root's) privileges so users can change their own password.
- **`2755`:** special `2` (SetGID), owner `7`, group `5`, others `5`. On a directory it shows as `drwxr-sr-x`. New files created inside keep the directory's group, which is useful for shared team folders.
- **`1777`:** special `1` (Sticky bit), everyone `7` (rwx). Shows as `drwxrwxrwt`. Everyone can create files, but only a file's owner (or root) can delete it. `/tmp` is the classic example.

A capital `S` or `T` instead of lowercase means the special bit is set but the matching execute permission isn't.

## Umask
Umask removes permissions from the defaults for new items. New files start at `666` and new directories at `777`. With a umask of `022`, new files become `644` and new directories `755`.

## Commands to practise
| Command | What it does |
|---|---|
| `ls -l` | Shows permissions, owner and group |
| `chmod 755 file` | Sets permissions using octal values |
| `chmod u+s file` | Turns on SetUID |
| `chmod g+s folder` | Turns on SetGID on a directory |
| `chmod +t folder` | Turns on the sticky bit |
| `chown user:group file` | Changes owner and group |
| `umask` | Shows the current umask |
| `id` | Shows your user ID, group ID and groups |

**Security note:** SetUID is powerful, so a badly configured SetUID program can give attackers administrator access. It should be used rarely and carefully.
